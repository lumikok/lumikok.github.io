# Agent 概念与设计原则

## 基本机制

Agent 不只是生成回答，还会根据目标和当前信息选择下一步行动，再根据结果继续处理。常见循环是：

```text
读取目标与当前信息 → 决定下一步 → 请求工具行动 → 观察结果 → 继续或结束
```

模型提出工具请求，程序负责校验、执行和回送结果。多步任务可以逐步拆解、调整，但不保证每次选择或最终结果正确；程序仍需限制工具权限、调用轮数和失败处理。

记忆是可选的工程机制：程序保存、检索并提供相关历史，不是模型天然能访问所有聊天窗口。根据反馈调整当前行动，也不等于修改模型权重或持续学会新能力；自动调试、优化和长期适应取决于具体实现。

## 设计原则

1. 协助人的工作。
2. 随时可用，但不应一直打扰用户。
3. 在任务需要时利用历史、结合当前情境并适应需求变化；持续性依赖实际的状态和记忆机制。
4. 无法保证结果总是正确，应给出依据和必要说明，避免用户盲目信任。
5. 透明、可控、一致：用户能够了解程序做了什么，允许终止或调整；相同条件下尽量保持稳定、可预测。
