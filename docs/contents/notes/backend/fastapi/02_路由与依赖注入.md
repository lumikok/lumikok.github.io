# FastAPI 路由与依赖注入

## 方法与路径

```python
from fastapi import FastAPI

app = FastAPI()

@app.patch("/tasks/{task_id}")
def update_task(task_id: int):
    return {"id": task_id}

@app.post("/tasks/{task_id}/complete")
def complete_task(task_id: int):
    return {"id": task_id}
```

HTTP 方法与路径共同决定接口。JSON 中传入 `status` 不会改成调用完成接口。

- 路径匹配但方法不支持：`405 Method Not Allowed`，检查请求方法和响应 `Allow` 头；
- JSON 中的 `status_code` 只是字段；实际状态码由路由 `status_code=...`、响应对象或异常决定；
- `404` 既可能是路径不存在，也可能是接口主动报告目标记录不存在，要结合响应与路由定位。

易错点：修改请求路径后仍保留旧方法，会得到 `405`。

## `APIRouter` 模块边界

```python
# routers/tasks.py
from fastapi import APIRouter

router = APIRouter(prefix="/tasks", tags=["tasks"])

@router.get("/")
def list_tasks():
    return []
```

```python
# main.py
from fastapi import FastAPI
from .routers.tasks import router

app = FastAPI()
app.include_router(router)
```

`APIRouter` 收集一组路由，`include_router()` 注册到应用；仅导入模块不会自动注册。上例路径是 `/tasks/`，`prefix` 可以在路由定义或注册时指定，注意不要重复添加。

路由模块组织 HTTP 接口；模型描述数据，数据库模块提供连接/会话。不要让路由模块反向导入主应用来注册自己，以免形成循环导入。

## `Depends` 提供资源

```python
from typing import Annotated
from fastapi import Depends

def get_limit():
    return 10

@router.get("/limited")
def list_limited(limit: Annotated[int, Depends(get_limit)]):
    return {"limit": limit}
```

`Depends(get_limit)` 传函数本身，由 FastAPI 调用并传入结果，不是写 `Depends(get_limit())` 提前执行。普通 Python 直接调用路由函数不会自动执行框架依赖注入。

## 复用校验与嵌套依赖

```python
from fastapi import Header, HTTPException

def verify_token(x_token: Annotated[str, Header()]):
    if x_token != "demo-secret":
        raise HTTPException(status_code=401, detail="Invalid token")
    return x_token

@router.get("/protected", dependencies=[Depends(verify_token)])
def protected():
    return {"ok": True}
```

装饰器的 `dependencies` 适合仅需执行校验、不需要返回值的情况；需要结果时放入函数参数。硬编码字符串只用于语法演示，不是完整认证方案。

```python
def get_db():
    return "database"

def get_user(db: Annotated[str, Depends(get_db)]):
    return {"name": "Alice"}

@router.get("/current")
def current(user: Annotated[dict, Depends(get_user)]):
    return user
```

框架按依赖关系先准备 `get_db`，再 `get_user`，最后执行路由。同一请求内默认复用相同依赖的结果；这不是跨请求永久缓存，必要时可以设置 `use_cache=False`。

使用 `yield` 的依赖可管理准备与清理，具体资源退出时机应结合框架版本、依赖 scope 和响应方式判断，不能一律说成“整个响应发完后”。
