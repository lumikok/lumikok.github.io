# 接口配置与中间件

## 路径操作配置

```python
from fastapi import FastAPI

app = FastAPI()

@app.post(
    "/items",
    status_code=201,
    tags=["items"],
    summary="创建记录",
    description="提交字段并创建一条记录。",
    response_description="创建后的记录",
    deprecated=False,
)
def create_item():
    return {"id": 1}
```

| 配置 | 作用 |
| --- | --- |
| `status_code` | 默认成功 HTTP 状态码，也用于文档 |
| `tags` | 文档分组，参数名是复数 |
| `summary` | 操作摘要 |
| `description` | 操作详细说明 |
| `response_description` | 成功响应的说明 |
| `deprecated=True` | 文档标记弃用，不禁用接口 |
| `include_in_schema=False` | 从文档隐藏，不禁止访问 |

标签可用继承 `str, Enum` 的枚举集中管理。响应字段和状态码应与真实接口一致，文档元数据不代替鉴权或业务校验。

## HTTP 中间件

```python
import time

@app.middleware("http")
async def measure_time(request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    response.headers["X-Process-Time"] = str(time.perf_counter() - start)
    return response
```

`call_next(request)` 将请求交给内部应用；等待返回后可修改响应。`perf_counter()` 适合测量耗时，避免系统时钟调整影响差值。

```text
请求 → 外层中间件 → 内层中间件 → 路由
响应 ← 外层中间件 ← 内层中间件 ← 路由
```

最后添加的中间件位于最外层，请求时先进入，响应时后退出。该计时通常不包含流式响应完整传输及全部后台工作的耗时。

中间件适合全局日志、请求追踪与通用响应头；路由依赖适合按接口提供资源或验证前置条件。CORS 等内置中间件通过 `app.add_middleware(...)` 注册。

参考：[路径操作配置](https://fastapi.tiangolo.com/tutorial/path-operation-configuration/)、[中间件](https://fastapi.tiangolo.com/tutorial/middleware/)。
