# Python 类方法与资源管理

普通函数、参数与 `lambda` 见[函数](./03_函数.md)，同步 `with` 见[文件操作](./08_文件操作.md)。

## `@classmethod` 与 `cls`

```python
class Parser:
    @classmethod
    def parse(cls, text):
        return cls()

obj = Parser.parse("example")
```

`@classmethod` 将方法绑定到类，第一个参数 `cls` 接收调用的类；实例方法的 `self` 接收实例。`cls` 是约定名称，不是关键字。Pydantic 字段验证器中的 `cls` 代表模型类，后面的 `value` 才是待校验字段值。实例方法基础见[面向对象](./06_面向对象.md)。

## `yield`：暂停与继续

```python
def numbers():
    yield 1
    yield 2

iterator = numbers()
assert next(iterator) == 1
assert next(iterator) == 2
```

含 `yield` 的函数调用后返回生成器，不立即执行函数体。`next()` 执行到下一个 `yield`，交出值并暂停；再次推进时从暂停处继续。结束后抛出 `StopIteration`。

在 pytest fixture 或 FastAPI 依赖中，框架负责推进生成器，将 `yield` 前的准备、提供的资源与后面的清理连接起来。普通生成器的清理不会仅因“写在 yield 后”就自动执行，应结合框架或上下文管理器的生命周期。

## `async`、`await` 与 `async with`

```python
async def read_tasks(session, statement):
    result = await session.exec(statement)
    return result.all()
```

`async def` 调用产生协程对象；`await` 等待可等待对象并在挂起时让事件循环处理其他任务，不代表自动并行或把阻塞调用变为非阻塞。

```python
async with AsyncSession(engine) as session:
    result = await session.exec(statement)
```

`async with` 使用异步上下文管理协议进入和退出资源范围，退出过程可以等待异步清理；同步 `with` 使用同步协议。是否加 `await` 由 API 决定，例如异步会话的 `commit()` 需要等待，`add()` 不需要。

真实易错点：关闭会话释放资源，不等于删除已提交记录；资源生命周期与数据生命周期要分别判断。

参考：[Python yield 表达式](https://docs.python.org/3/reference/expressions.html#yield-expressions)、[异步上下文管理器](https://docs.python.org/3/reference/datamodel.html#asynchronous-context-managers)。
