# 迭代与递归

迭代用循环重复执行步骤，递归用函数调用自身处理子问题。分析两者都要统计实际工作量，递归还需考虑调用栈。

## 迭代

循环体为常数开销时，时间复杂度由执行次数决定：逐个遍历 `n` 项是 O(n)，每轮将问题规模减半通常是 O(log n)。两层循环只有在总执行次数为 O(n²) 时才是平方复杂度，不能只数嵌套层数；循环体内的排序、查找等工作也要计入。

## 递归

<u>递归是一种算法策略</u>，它通过函数调用自身来解决问题。它主要包括两个阶段：

1. **递**：程序不断调用自身，逐渐将参数简化或更小化，直到达到“终止条件”。
2. **归**：当达到“终止条件”后，程序从最深层的调用开始返回结果，汇聚每一层的结果，最终得到最终答案。

可知递归代码主要包含三个要素：

1. **终止条件**：用于决定什么时候由“递”转为“归”。
2. **递归调用**：函数在自身内部调用自身。
3. **处理子问题结果**：按问题需要合并返回值或更新状态；有些遍历函数返回 `void`。

计算 `1` 到 `n` 的和（下述求和示例要求 `n >= 1`，且结果不超过 `int` 范围）：

```c
int recur(int n){
    // 终止条件
    if(n==1)
        return 1;
    // 递
    int res = recur(n-1);
    // 归
    return n + res;
}
```

## 迭代与递归的比较

同一问题可以有两种写法。以 `f(n)=1+2+...+n` 为例：

- **迭代**：从 1 开始，逐步累加到 n。
- **递归**：就是先拆成 f(n)=n+f(n-1)，然后继续拆 f(n-1)，直到 f(1)=1 为止，然后逐步汇聚结果。

### 调用栈

通常的递归实现需要为尚未返回的调用保存参数、局部变量和返回位置，每层调用各自独立。若深度为 `d`、每层额外存储为 O(1)，调用栈空间为 O(d)。上面的求和深度为 O(n)，而逐项累加的迭代版只需 O(1) 额外空间；具体机制见[DFS 中的递归调用与局部变量](../searching/06_DFS.md)。

函数调用有额外开销，但总耗时仍取决于算法、实现和编译优化，不能仅因使用递归就判定更慢。调用栈容量有限，过深的递归可能栈溢出。

### 尾递归

尾递归把递归调用的结果直接返回，调用返回后没有其他运算。求和时可把已累计的结果作为参数传下去，使编译器有机会将递归优化为循环、复用栈帧。**写成尾递归不保证发生优化**；未优化时仍需按递归深度计算栈空间，具体取决于语言实现、编译器、选项等条件。

仍以计算 `1` 到 `n` 的和为例，初始调用为 `tailRecur(n, 0)`：

```c
int tailRecur(int n, int res){
    // 终止条件
    if(n==1)
        return res + 1;//这里的res就是存储和
    // 递归调用是函数的最后一个操作
    return tailRecur(n-1, res + n);
}
```

### 递归树

当处理与“分治”相关的算法问题时，递归往往比迭代更为直观和简洁。  
以斐波那契数列为例，要求 `n >= 0` 且结果可由 `int` 保存：

```c
int fib(int n){
    //终止条件（前两个值）
    if (n==0 || n==1)
    return n;
    //递归调用
    int res = fib(n-1) + fib(n-2);
    //返回结果
    return res;
}
```

**该函数递归树图示**：

```plaintext
              fib(4)
             /      \
         fib(3)     fib(2)
        /     \    /     \
    fib(2) fib(1) fib(1) fib(0)
    /   \
fib(1) fib(0)
```

同一个 `fib(k)` 会在不同分支重复计算。该朴素实现的时间呈指数增长，可用 O(2ⁿ) 作上界；最深调用链只有 O(n) 层，因此栈空间是 O(n)，不是按整棵调用树的节点数计算。

### 对照

下表总结了迭代与递归的主要区别：

|          | 迭代                   | 递归                                     |
| -------- | ---------------------- | ---------------------------------------- |
| 实现方式 | 通过循环结构实现       | 通过函数调用自身实现                     |
| 时间分析 | 统计总迭代次数与循环体开销 | 统计调用次数与每次调用的工作量 |
| 空间分析 | 统计显式使用的数据结构 | 同时统计数据结构与最深未返回调用链 |
| 适用场景 | 适用于简单重复任务     | 适用于子问题分解，如树、图、分治、回溯等 |

尾递归优化参考：[GCC 的尾调用优化选项](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html#index-foptimize-sibling-calls)。
