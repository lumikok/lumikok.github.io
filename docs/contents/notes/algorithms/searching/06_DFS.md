# 深度优先搜索

DFS 沿一个分支继续深入，当前分支处理完后回到调用处，再处理下一个分支。递归实现中，函数调用栈保存了“返回哪里继续执行”，不需要手动记录每一层的执行位置。

DFS 不只是寻找路径，也可以让孩子先计算结果，再由父节点汇总。普通 DFS 的首次到达不保证最少步数；等代价最短步数的层序机制见[广度优先搜索](07_BFS.md)。

## 先约定递归函数返回什么

以有根树的子树大小为例，约定：

`subtreeSize(u)` 返回以 `u` 为根的整棵子树的节点数，包含 `u` 自身。

树用孩子列表 `children[u]` 表示，只保存从父节点指向孩子的关系。下面是说明返回累计过程的示例，不是某道题的原始训练源码：

```cpp
#include <vector>
using namespace std;

// 前提：children 表示一棵有根树，u 是其中的合法节点。
int subtreeSize(int u, const vector<vector<int>>& children) {
    int total = 1;  // 1. 先计入当前节点；每次调用各有自己的 total。

    for (int v : children[u]) {
        // 2. 当前调用暂停，等孩子整棵子树处理完成后取得结果。
        int childSize = subtreeSize(v, children);
        total += childSize;  // 3. 合并到当前调用的累计量。
    }
    return total;  // 4. 所有孩子处理完，再把完整摘要交给父节点。
}
```

叶子没有孩子，循环不执行，直接返回 `1`，因此无需额外写一个叶子特判。树结构按只读引用传入，各层使用同一份孩子列表，不在每次递归时复制整棵树。

### 局部变量不会被孩子的同名变量覆盖

调用孩子时，父节点的 `total` 保留在自己的调用中；孩子创建自己的 `total`。孩子返回后，父节点从调用语句继续，取得返回值并加到自己的累计量中。这里独立的是每次调用的局部标量，不是把全局变量自动复制了一份。

对于链 `1→2→3`：

- 进入顺序为 `1、2、3`。
- 节点 `3` 没有孩子，返回 `1`。
- 节点 `2` 收到 `1`，加上自己，返回 `2`。
- 节点 `1` 收到 `2`，加上自己，返回 `3`。

不要把 `total` 改成一个所有调用共用、每次进入都重置的全局累计量，那会破坏各节点尚未完成的统计。

## 什么时候访问，什么时候汇总

“进入节点”和“完成节点”是两个不同的时刻：

- 进入时，节点自身的信息已知，可以先处理自身，再递归孩子。
- 所有孩子返回后，整棵子树的信息才完整，适合计算子树大小、颜色差值或判断该子树是否满足条件。

因此“首次访问到了节点”不等于“已经算好了它的子树”。若在孩子返回前判断子树结果，就只看到了部分信息。前序、后序体现的正是处理自身与递归孩子的先后关系，已有分类见[二叉树遍历](../data-structures/binary-tree/02_二叉树遍历.md)；孩子列表的树不要求每个节点最多两个孩子。

## 返回摘要与累计答案是两种职责

返回值应是父节点继续计算时需要的信息，不必与最终输出相同。

例如统计黑白节点数相等的子树：

- `dfs(u)` 向父节点返回“当前子树的黑节点数减白节点数”。
- 当前调用在全部孩子返回后，判断自己的差值是否为零；若为零，为共享答案增加一次计数。

父节点需要孩子的差值来判断自己的子树是否平衡，并不需要把“平衡子树数量”当成差值相加。只要每个节点都恰好贡献一次判断，最终数量就可以独立累计；根节点返回的差值也不能直接作为答案输出。具体实现见[CF1676G 题解](../../../problems/dfs.md#cf1676g-子树差值与答案计数)。

若确实需要向父节点返回多种信息，也可以返回结构体等复合结果；先确定信息含义，再选择语法，不为使用某种返回类型增加多余状态。

## 表示方式、复杂度与递归边界

本页示例只保存父到子的边，每个非根节点只有一个父节点，因此从根调用时，每个节点恰好进入一次，不需要额外的访问标记。若把无向树的边双向保存，必须排除返回父节点的那条边；一般有环图还需要访问标记，不能直接套用孩子列表的循环。

子树大小的代码虽然在递归中包含循环，但所有调用合计只遍历 `n-1` 条父子边，因此总时间为 O(n)，不是 O(n²)。孩子列表占 O(n) 空间；递归调用栈占 O(h)，`h` 为树高，总空间为 O(n)。

链形树的最深调用层数为 `n`，不能因为只写了一个递归函数就把栈空间算成 O(1)。递归深度还受运行环境的栈容量限制；数据规模扩大时，需要重新评估，不能仅凭总时间为线性就断言一定安全。
