# 最小可行值二分

有些题目不是在数组中查找某个元素，而是在一组可能的答案中寻找满足条件的最小值。关键是先写出一个判定函数 `feasible(limit)`：答案上限为 `limit` 时，任务能否完成？

## 为什么可以二分答案

若 `limit` 可行，那么更宽松的上限也可行；若 `limit` 不可行，那么更严格的上限也不可行。于是答案范围形成“不行、不行、……、可行、可行”的单调序列，可以二分第一个可行值。

以“将非负数序列分成至多 `m` 段，使最大段和尽量小”为例：

1. 下界是单个元素的最大值，因为每段都必须容纳其中的元素。
2. 上界是所有元素之和，因为整段放在一起一定可行。
3. 给定上限 `limit`，从左到右累加；若加入下一个元素会超出上限，就另起一段。这样得到所需的最少段数。
4. 若段数不超过 `m`，`limit` 可行，否则不可行。

这套贪心判定依赖元素非负。若允许负数，“超出上限就立即分段”未必得到最少段数，不能直接套用。

## 二分循环的不变量

使用闭区间 `[left, right]` 时，维护“最小可行值仍在当前区间内”。每次都把 `mid` 排除，确保区间收缩：

```text
left  = 单个元素的最大值
right = 所有元素之和
while left < right:
    mid = left + (right - left) / 2
    if feasible(mid):
        right = mid       // mid 可行，答案可能就是它
    else:
        left = mid + 1    // mid 不可行，只能找更大的上限
return left
```

这里使用 `left < right`，可行时保留 `mid` 是安全的：只要进入循环，`mid < right`，所以 `right = mid` 仍会缩小区间。这与普通闭区间查找的 `left <= right` 循环不同，不能混用更新规则。若元素之和可能超过 `int` 范围，上界、中点和段和应使用更宽的整数类型。
