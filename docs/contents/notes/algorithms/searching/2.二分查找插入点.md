# 二分查找插入点

二分查找可以找目标值，也可以找它的插入位置。插入点只是一个下标，不表示已经把元素插入数组。

## 无重复元素

有序数组中没有重复元素时，普通二分若找到目标，可以直接返回该位置；若没有找到，循环结束后的 `left` 就是插入位置。此时 `left` 指向第一个大于目标的元素，也可能等于数组长度。

## 有重复元素：最左插入点

有重复元素时，“找到任意一个等值元素”不等于“找到最左插入点”。最左插入点也叫 `lower_bound`：它是第一个 **大于或等于** `target` 的位置。如果所有元素都小于目标，返回 `len`。

```c
int lowerBound(const int *array, int len, int target) {
    int left = 0;
    int right = len - 1;

    // 始终在闭区间 [left, right] 中寻找第一个 >= target 的位置。
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (array[mid] >= target) {
            right = mid - 1;  // mid 可能是答案，继续向左找更早的位置。
        } else {
            left = mid + 1;   // [left, mid] 都不可能是答案。
        }
    }

    return left;
}
```

### 插入点与实际命中

`lowerBound` 总会返回 `[0, len]` 内的插入位置，但目标不一定存在。若要判断是否找到目标，必须先检查下标再读取数组：

```c
int contains(const int *array, int len, int target) {
    int pos = lowerBound(array, len, target);
    return pos < len && array[pos] == target;
}
```

这个顺序也覆盖空数组：`len == 0` 时返回 `0`，短路求值使 `array[0]` 不会被访问。曾在循环前读取 `array[right]`，空数组下 `right == -1`，会越界；循环后若 `pos == len`，直接读取 `array[pos]` 也会越界。

### 先看循环能否自然覆盖边界

2026-09-27 复查时，`lower_bound` 与 `upper_bound` 的核心循环正确，问题来自循环前读取 `a[r]` 的额外判断。删除这项判断后，空数组使循环直接跳过，返回 `left == 0 == len`；非空数组中若没有满足条件的元素，循环也会自然返回 `len`。精确查找的未命中约定仍是 `-1`，不能混为一谈。

同一天的 P1996 暴露了相似问题：每轮先固定移动一次，再处理剩余次数，会让 `m=1` 的行为偏离题意。改为“移动 `m-1` 次，再淘汰当前元素”，`m=1` 自然对应零次移动。

可迁移的检查方法是：先写出每轮应该完成的动作与区间含义，再代入最小合法输入，检查循环执行零次时是否已经得到正确结果。必要的输入检查仍应保留；额外特判如果提前访问数据或改变每轮动作，就可能破坏原来的约定。

这两处都是提示下修正，尚不能记为无提示掌握；历史单题 AC 也不能替代边界验收。

## 复杂度

数组支持 O(1) 的下标访问，因此二分需要 O(log n) 时间和 O(1) 额外空间。实际插入元素仍可能需要移动后续元素，不能把“找到插入点”的复杂度当成“完成插入”的复杂度。
