# 排序实现中的区间、不变量、稳定性与退化

这篇笔记不重复介绍每种排序算法，而是记录实现时真正容易出错的判断依据：区间是什么、循环结束后应保证什么、稳定性由哪一行代码决定，以及什么输入会让算法退化。

## 先写清区间与不变量

写循环前，先用一句话说明当前区间的含义。它比背循环模板更可靠。

| 算法 | 每轮需要维持的事实 |
| --- | --- |
| 选择排序 | `[0, i)` 已经有序，只在 `[i, n)` 中选择最小值 |
| 冒泡排序 | 一轮结束后，未排序区间的最大值位于区间末尾 |
| 插入排序 | 插入 `a[i]` 之前，`[0, i)` 已经有序 |
| 快速排序 | 分区结束后，基准位于最终位置，再递归处理两侧 |
| 归并排序 | 合并前左右两段分别有序，合并后整个区间有序 |

数组长度为 `n` 时，最后一个合法下标是 `n - 1`。只要循环会访问 `a[j]`，就应把条件翻译成下标区间检查，而不是凭感觉写 `<=`。

## 踩坑 1：选择排序把已排序前缀又扫了一遍

曾出现两个连续问题：先把已排序前缀纳入扫描，修正起点后又把上界写成 `j <= n`，访问了 `a[n]`。

正确判断不是记住一段循环，而是从不变量推出范围：

```c
// [0, i) 已经有序，只在 [i, n) 中找最小值。
for (int j = i + 1; j < n; j++) {
    // 比较 a[j] 与当前最小值
}
```

复查问题：当前扫描是否跳过了已排序前缀？循环体中的每个下标是否都小于 `n`？

## 踩坑 2：有序输入不代表快速排序无需递归

固定选择首元素为基准时，升序数组的首元素恰好是最小值。一次分区只能确定这一个元素的位置，剩余 `n - 1` 个元素仍会继续递归：

```text
n -> n - 1 -> n - 2 -> ... -> 1
```

因此递归深度会达到 O(n)，总时间退化为 O(n²)。判断快排是否会退化，应看每次划分是否均衡，而不是看输入是否“已经有序”。随机基准、三数取中或三路划分只能降低特定退化风险，不能把普通快排变成稳定排序。

## 踩坑 3：稳定性必须落到比较和遍历方向

“归并排序稳定”只是结论，代码仍可能写成不稳定版本。合并时若左右元素相等，必须先取左侧元素：

```cpp
if (left[i] <= right[j]) {
    result.push_back(left[i]);
}
```

若写成 `left[i] < right[j]` 并在 `else` 中取右侧，相等元素的先后顺序会被颠倒。

计数排序的稳定回填同理：前缀和给出相同键的末尾位置，因此必须从原数组末尾向前放置。若正序回填，同键记录的相对顺序会反转。

## 踩坑 4：计数数组长度不是原数组长度

计数排序同时存在两个容易混淆的长度：

- `n`：原数组长度，决定要读取多少个待排序元素。
- `k`：值域长度，决定计数数组的大小与遍历范围。

稳定回填遍历的是原数组，所以边界来自 `n`；只有统计数组的初始化、前缀和等步骤才按 `k` 遍历。变量名应直接表达 `size`、`range` 或 `count_size`，避免只写含义模糊的 `len`。

## 踩坑 5：把并列要求落实为第二关键字

题目要求“值尽量大，相同时取最小原编号”，就有两个排序关键字：值降序、原编号升序。只比较值，不能决定同值记录中哪一个排在前面；`std::sort` 不承诺保留它们的输入顺序。

下面从月赛训练文件 `01_date/2026-10/yuesai/d.cpp` 的比较函数整理，重命名字段并改为只读引用参数：

```cpp
struct RankedItem {
    long long value;
    int originalIndex;
};

bool valueDescendingIndexAscending(const RankedItem& a, const RankedItem& b) {
    if (a.value != b.value) return a.value > b.value; // 1. 先比较主要目标。
    return a.originalIndex < b.originalIndex;       // 2. 同值才比较原编号。
}
```

例如 `(值,编号)` 为 `(5,4)、(5,2)、(3,1)`，排序后应为 `(5,2)、(5,4)、(3,1)`。后续若二分第一个合适的值，同值组最前面的记录才同时满足最小编号要求。原编号必须在排序前保存，不能用排序后的数组下标替代。

比较函数要满足严格弱序，不能把最后一行改成 `<=`，否则自己与自己比较也会返回真。`stable_sort` 能保留等价元素的原相对顺序，但只有原顺序恰好就是题目要求的次序时，这种保留才足够；显式写出第二关键字更直接。接口要求见 [C++ 排序规范](https://eel.is/c++draft/alg.sorting)。具体查询例子见[月赛 D：排序与首个可行位置](../../../problems/sorting.md#月赛-d-排序与首个可行位置)。

## 实现后的最小检查清单

1. 写出每个循环处理的半开区间，例如 `[i, n)`。
2. 检查最后一次迭代访问的确切下标。
3. 用空数组、单元素、有序、逆序和大量重复值测试。
4. 若声称稳定，用带原始编号的相同键记录验证相对顺序。
5. 若使用递归，构造最不均衡的输入检查递归深度。
