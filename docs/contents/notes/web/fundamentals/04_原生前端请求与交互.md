# 原生前端请求与交互

以 FastAPI 为后端，围绕“读取表单 → 发送请求 → 更新页面”组织浏览器交互。基础语法复用[HTML 入门](./01_HTML入门.md)、[JavaScript 入门](./03_JS入门.md)和[表单与按钮](../html/08_表单与按钮.md)；布局见[布局与响应式](../css/09_布局与响应式.md)。

下列代码是按原笔记整理的示意片段，`API_URL`、`TOKEN`、列表和图表刷新函数需由具体页面提供。字段与请求方法按接口契约调整。

## 请求流程

```text
HTML 表单 → JavaScript 对象 → JSON 请求体 → FastAPI
        ← DOM 更新     ← JSON 响应    ←
```

## HTML 表单

```html
<form id="expense-form">
  <label for="amount">金额</label>
  <input id="amount" name="amount" type="number" step="0.01" required />

  <label for="category">分类</label>
  <select id="category" name="category" required>
    <option value="餐饮">餐饮</option>
    <option value="交通">交通</option>
  </select>

  <label for="note">备注</label>
  <input id="note" name="note" type="text" />

  <button type="submit">保存</button>
</form>
```

`id` 用于查询元素，`label[for]` 对应控件的 `id`，`name` 才是 `FormData` 中的字段名。控件没有 `name` 时不会进入表单数据；`option.value` 是实际提交值，必须符合后端枚举。

## DOM 查询与事件绑定

```javascript
const form = document.querySelector("#expense-form");
const list = document.querySelector("#expense-list");
const status = document.querySelector("#request-status");

form.addEventListener("submit", async (event) => {
  event.preventDefault();
  await submitForm();
});
```

页面除表单外，还需提供 `#expense-list` 列表与 `#request-status` 提示元素。`submit` 可以由按钮或回车触发，`preventDefault()` 阻止默认跳转或刷新。

查询不到元素会返回 `null`。遇到 `Cannot read properties of null` 时，检查元素是否存在、选择器及 HTML 属性是否拼写正确，以及脚本是否在元素创建前执行。更新纯文本用 `textContent`，创建列表项可用 `createElement("li")` 后 `append`。

绑定事件时传函数，不能在渲染中直接执行请求：

```javascript
deleteButton.addEventListener("click", () => deleteTask(task.id));
// deleteButton.addEventListener("click", deleteTask(task.id)); // 注册时就执行了删除。
```

`fn` 是函数对象，`fn()` 是立即调用，`() => fn(id)` 则把带参数调用留到事件触发时执行。参考：[MDN：addEventListener](https://developer.mozilla.org/en-US/docs/Web/API/EventTarget/addEventListener)。

## 读取表单

```javascript
function readExpensePayload(form) {
  const formData = new FormData(form);
  return {
    amount: Number(formData.get("amount")),
    category: formData.get("category"),
    note: formData.get("note") || null,
  };
}
```

这些文本和数字控件取出的值是字符串，金额需转换为数字，空备注按接口约定转为 `null`。`FormData` 也能包含文件，不能把所有字段一概当成字符串。

`JSON.stringify(payload)` 再把 JavaScript 对象序列化为 JSON 请求体；对象与 JSON 字符串是不同的值。字段名必须完全一致，`note` 与 `notes` 是两个字段；可选字段要用非空内容测试，避免拼写错误被默认空值掩盖。

## GET 请求

```javascript
async function loadExpenses() {
  const response = await fetch(API_URL, {
    headers: {
      "X-Token": TOKEN,
    },
  });

  if (!response.ok) {
    throw new Error(`加载失败：${response.status}`);
  }

  const expenses = await response.json();
  return expenses;
}
```

- `fetch()` 返回 `Response`，不是接口数据；
- `response.json()` 把 JSON 响应体解析成 JavaScript 数据；
- GET 是默认方法，可以省略 `method: "GET"`；
- 空数组 `[]` 表示请求成功但没有数据，不是报错。

`async` 函数返回 Promise；这里 `fetch()` 等待响应，`response.json()` 再异步读取并解析响应体，需要分别 `await`。HTTP 状态失败要主动抛错，网络失败、解析失败及主动抛出的错误交由调用方的 `try...catch` 处理。

## POST 请求

```javascript
const response = await fetch(API_URL, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Token": TOKEN,
  },
  body: JSON.stringify(payload),
});

if (!response.ok) {
  const detail = await response.text();
  throw new Error(`创建失败：${response.status} ${detail}`);
}
```

`method` 选择请求方法，`Content-Type` 声明请求体格式，`body` 放序列化后的数据；`X-Token` 是本项目约定的认证头。

`fetch()` 遇到 `404`、`422`、`500` 时通常仍返回 `Response`，所以必须检查 `response.ok`。参考：[MDN：使用 Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)。

## 编辑回填与请求方法切换

```javascript
let editingId = null;

function startEditing(record) {
  editingId = record.id;
  form.elements.namedItem("amount").value = record.amount;
  form.elements.namedItem("category").value = record.category;
  form.elements.namedItem("note").value = record.note ?? "";
}

async function save(payload) {
  const isEditing = editingId !== null;
  const url = isEditing ? `${API_URL}/${editingId}` : API_URL;
  const response = await fetch(url, {
    method: isEditing ? "PUT" : "POST",
    headers: { "Content-Type": "application/json", "X-Token": TOKEN },
    body: JSON.stringify(payload),
  });
  if (!response.ok) throw new Error(`保存失败：${response.status}`);
}
```

控件的 `.value` 用于回填，`?? ""` 仅把 `null`、`undefined` 转为空字符串。用独立 id 保存编辑状态，同时切换 URL 和方法；接口约定部分更新时使用 `PATCH`。保存失败保留输入，取消或确认保存成功后清除 id，避免下次新增仍更新旧记录。

## 提交成功后的处理

确认写入成功后，清除编辑状态、重置表单，再刷新列表与图表。`form.reset()` 恢复控件的初始默认值，不一定全部清空，也不会自动更新展示数据；列表和图表是同一数据源的派生视图，应一起刷新。

### 写入成功不等于刷新成功

写请求与刷新 GET 是两个步骤，错误提示要能区分它们：

```javascript
async function saveAndRefresh(payload) {
  try {
    await save(payload);
  } catch (error) {
    status.textContent = `未确认保存成功：${error.message}`;
    return;
  }

  editingId = null;
  form.reset();
  try {
    await Promise.all([loadExpenses(), loadCharts()]);
    status.textContent = "已保存，刷新成功";
  } catch (error) {
    status.textContent = "已保存，但刷新失败，请重新查询";
  }
}
```

此例演示阶段控制；实际 `loadExpenses()` 还需把返回数据渲染到列表，`loadCharts()` 负责更新图表。使用独立提示元素，避免写提示时覆盖列表内容。

POST、PATCH、DELETE 都应区分写入与展示阶段。刷新失败应重试查询，不能据此推断写入回滚或重复写入；网络中断时服务端也可能已提交，需要查询核实，或使用接口提供的幂等机制。`location.reload()` 会重载整个页面，局部刷新只重新获取和渲染相关数据。

## 保存期间禁用与恢复

`disabled` 不会清空控件的 `.value`，但禁用控件不会进入 `FormData`，因此先读取并转换数据，再锁定控件。

```javascript
let saving = false;

async function submitForm() {
  if (saving) return;
  const payload = readExpensePayload(form);
  const controls = [...form.querySelectorAll("input, select, textarea, button")];
  const previousDisabled = controls.map((control) => control.disabled);
  saving = true;
  controls.forEach((control) => { control.disabled = true; });
  try {
    await saveAndRefresh(payload);
  } finally {
    controls.forEach((control, index) => {
      control.disabled = previousDisabled[index];
    });
    saving = false;
  }
}
```

- 原本因业务规则禁用的控件仍应禁用，不能在 `finally` 中一律启用；每个操作只恢复自己锁定的控件。
- 若允许关闭弹窗，关闭按钮与 Escape 处理也应检查保存状态。
- 前端校验与禁用改善体验，不能代替后端校验和权限检查。

参考：[MDN：FormData 构造函数](https://developer.mozilla.org/en-US/docs/Web/API/FormData/FormData)。

## 查询参数与分页

```javascript
const pageSize = 10;
const skip = (page - 1) * pageSize;
const limit = pageSize + 1;

const params = new URLSearchParams({
  skip: String(skip),
  limit: String(limit),
});

if (category) {
  params.set("category", category);
}

const response = await fetch(`${API_URL}?${params}`, {
  headers: {
    "X-Token": TOKEN,
  },
});

if (!response.ok) throw new Error(`加载失败：${response.status}`);
const rows = await response.json();
const currentRows = rows.slice(0, pageSize);
const hasNextPage = rows.length > pageSize;
nextButton.disabled = !hasNextPage;
```

- `URLSearchParams`：生成并编码 URL 查询参数；
- `skip = (page - 1) * pageSize`：跳过前面页面的数据；
- 请求 `pageSize + 1` 条：多取一条，用于判断是否还有下一页；
- `slice(0, pageSize)`：只显示当前页应有的数据；
- `rows.length > pageSize`：多取的一条存在时，说明下一页还有数据；
- `disabled`：控制“下一页”按钮是否可用。

这种“多取一条”的方法不需要后端额外返回总条数，但只能判断是否存在下一页。

筛选条件变化后，应把页码重置为第一页，再按新条件请求；否则旧页码可能让新筛选结果看起来为空。删除当前页最后一项后，也应处理空页或回退。分页顺序需要后端稳定排序支持。

## 接口数据转换为图表数据

图表库需要有尺寸的 DOM 容器，然后才能创建实例并设置配置：

```html
<div id="category-chart" style="width: 600px; height: 320px"></div>
<div id="daily-chart" style="width: 600px; height: 320px"></div>
```

```javascript
const categoryChart = echarts.init(
  document.querySelector("#category-chart"),
);

categoryChart.setOption({
  series: [
    {
      type: "pie",
      data: categorySummary.map((item) => ({
        name: item.category,
        value: item.amount,
      })),
    },
  ],
});
```

基本链路：

```text
有尺寸的 DOM 容器 → 图表实例 → option/series → setOption()
```

接口响应结构通常不等于图表库的数据结构，需要用 `.map()` 转换数据契约：

- 饼图：每项转换为 `{ name, value }`；
- 折线图：分别生成类别横轴数组和数值数组。

```javascript
const dailyChart = echarts.init(document.querySelector("#daily-chart"));
const dates = dailySummary.map((item) => item.date);
const amounts = dailySummary.map((item) => item.amount);

dailyChart.setOption({
  xAxis: {
    type: "category",
    data: dates,
  },
  yAxis: {
    type: "value",
  },
  series: [
    {
      type: "line",
      data: amounts,
    },
  ],
});
```

聚合接口中的字段语义：

- `amount`：已经是该组记录的金额总和；
- `count`：该组包含的记录数；
- 不能再计算 `amount * count`，否则会重复累计。

新增、编辑或删除数据后，列表和图表都是同一数据源的派生视图，需要一起刷新：

```javascript
await Promise.all([loadExpenses(), loadCharts()]);
```

排错时先用静态数据调用 `setOption()`，确认容器尺寸、实例和图表配置正确，再连接真实接口。这样可以区分渲染问题与数据问题。

## FastAPI 托管前端

FastAPI 可以同时提供 API 和静态前端，实现单端口访问：

```python
from fastapi.staticfiles import StaticFiles

# 先注册 API 路由
app.include_router(expenses_router)
app.include_router(summary_router)

# 最后把前端挂载到根路径
app.mount("/", StaticFiles(directory="frontend", html=True), name="frontend")
```

路由按注册顺序匹配。挂载到 `/` 的静态文件应用能够匹配任意剩余路径，因此应放在 API 路由之后，避免 API 请求先被静态文件处理。

前端和 API 同源后，可以使用根相对 URL：

```javascript
const response = await fetch("/expenses");
```

`/expenses` 会从当前页面的协议、主机和端口发出请求。这里省略的不是单独的端口号，而是复用整个当前 Origin。

单端口同源可以省去这组前后端之间的 CORS 配置，但请求方法、请求头、数据格式和后端校验仍然不变。

## CORS

协议、主机、端口任意一项不同，就是不同源：

```text
http://127.0.0.1:5500
http://127.0.0.1:8000
```

FastAPI 配置：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://127.0.0.1:5500"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

- CORS 是浏览器的跨源读取限制；
- `allow_origins` 必须包含前端页面的来源；
- JSON 请求或自定义请求头通常会触发 `OPTIONS` 预检；
- 接口能直接打开，不代表网页中的跨源 `fetch` 一定成功；
- 缺少 `Access-Control-Allow-Origin` 时，浏览器会阻止 JavaScript 读取响应。

如果业务接口和 `/openapi.json` 同时返回 `404`，先确认当前端口运行的是不是目标应用。请求发到错误服务时，路由不存在才是根因，浏览器显示的 CORS 报错可能只是次级现象，不能直接靠修改跨域配置解决。

## 排错顺序

| 层次 | 检查内容 |
| --- | --- |
| DOM | 选择器是否找到元素，事件是否触发 |
| 表单 | 是否有 `name`，`FormData` 的键和值是否正确 |
| 请求 | URL、方法、请求头、Request Payload |
| CORS | `OPTIONS` 和 `Access-Control-Allow-Origin` |
| 后端 | 状态码、响应体、`422` 校验信息 |
| 数据库 | 数据是否真的新增或修改 |
| 渲染 | GET 已返回数据，但 DOM 是否正确更新 |

Console 报错还要检查脚本来源。`content*.js` 等文件可能由浏览器扩展注入，不一定是项目代码。
