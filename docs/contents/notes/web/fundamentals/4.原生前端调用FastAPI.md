# 原生前端调用 FastAPI

本文以 FastAPI 为后端示例；其中 HTML 表单、DOM、事件、`FormData`、`async/await`、`fetch`、JSON、错误处理和 CORS 都是可迁移的浏览器前端知识，换用其他 HTTP 后端时只需调整接口 URL、字段、认证方式和跨域配置。本文基本不涉及 CSS。

## 请求流程

```text
HTML 表单 → JavaScript 对象 → JSON 请求体 → FastAPI
        ← DOM 更新     ← JSON 响应    ←
```

## HTML 表单

```html
<form id="expense-form">
  <label for="amount">金额</label>
  <input id="amount" name="amount" type="number" step="0.01" required />

  <label for="category">分类</label>
  <select id="category" name="category" required>
    <option value="餐饮">餐饮</option>
    <option value="交通">交通</option>
  </select>

  <label for="note">备注</label>
  <input id="note" name="note" type="text" />

  <button type="submit">保存</button>
</form>
```

| 属性 | 作用 |
| --- | --- |
| `id` | 元素的唯一标识，也可供 JavaScript 查询 |
| `label[for]` | 对应控件的 `id` |
| `name` | 提交字段名，也是 `FormData` 中的键 |
| `option[value]` | 下拉框实际提交的值 |
| `required` | 浏览器要求该字段必填 |

- `for`、`id`、`name` 作用不同，只是经常写成相同值；
- 控件没有 `name` 时，不会进入 `FormData`；
- `option` 显示的文字不一定等于提交的 `value`；
- `value` 必须符合后端枚举，例如后端接受 `餐饮` 时不能提交 `food`。

## DOM 操作

```javascript
const form = document.querySelector("#expense-form");
const list = document.querySelector("#expense-list");

list.textContent = "加载完成";
```

- `document.querySelector("CSS 选择器")`：返回第一个匹配的元素；
- `textContent`：读取或修改元素的纯文本；
- 查询不到元素时返回 `null`。

出现 `Cannot read properties of null` 时，按顺序检查：

1. 元素是否确实存在；
2. 选择器中的 `id` 或 `class` 是否与 HTML 完全一致；
3. HTML 属性是否有拼写错误或多余的逗号等符号；
4. JavaScript 是否在元素创建前执行。

创建并插入元素：

```javascript
const item = document.createElement("li");
item.textContent = "交通：20 元";
list.append(item);
```

## 事件

```javascript
form.addEventListener("submit", async (event) => {
  event.preventDefault();
  // 提交逻辑
});
```

- `addEventListener(事件名, 回调函数)`：注册事件处理函数；
- `submit`：表单提交事件，点击提交按钮或按回车都能触发；
- `preventDefault()`：阻止表单跳转或刷新页面；
- `async (event) => {}`：异步箭头函数。

## `async` 与 `await`

```javascript
async function loadExpenses() {
  const response = await fetch(API_URL);
  const data = await response.json();
  return data;
}
```

- `async` 函数一定返回 Promise；
- `await` 等待 Promise 完成；
- `await` 通常写在 `async` 函数内部；
- `fetch()` 和 `response.json()` 是两个异步步骤，所以分别需要 `await`。

## GET 请求

```javascript
async function loadExpenses() {
  const response = await fetch(API_URL, {
    headers: {
      "X-Token": TOKEN,
    },
  });

  if (!response.ok) {
    throw new Error(`加载失败：${response.status}`);
  }

  const expenses = await response.json();
  return expenses;
}
```

- `fetch()` 返回 `Response`，不是接口数据；
- `response.json()` 把 JSON 响应体解析成 JavaScript 数据；
- GET 是默认方法，可以省略 `method: "GET"`；
- 空数组 `[]` 表示请求成功但没有数据，不是报错。

## 查询参数与分页

```javascript
const pageSize = 10;
const skip = (page - 1) * pageSize;
const limit = pageSize + 1;

const params = new URLSearchParams({
  skip: String(skip),
  limit: String(limit),
});

if (category) {
  params.set("category", category);
}

const response = await fetch(`${API_URL}?${params}`, {
  headers: {
    "X-Token": TOKEN,
  },
});

const rows = await response.json();
const currentRows = rows.slice(0, pageSize);
const hasNextPage = rows.length > pageSize;
nextButton.disabled = !hasNextPage;
```

- `URLSearchParams`：生成并编码 URL 查询参数；
- `skip = (page - 1) * pageSize`：跳过前面页面的数据；
- 请求 `pageSize + 1` 条：多取一条，用于判断是否还有下一页；
- `slice(0, pageSize)`：只显示当前页应有的数据；
- `rows.length > pageSize`：多取的一条存在时，说明下一页还有数据；
- `disabled`：控制“下一页”按钮是否可用。

例如 `page = 3`、`pageSize = 2`：

```text
skip = (3 - 1) × 2 = 4
limit = 2 + 1 = 3
```

这种“多取一条”的方法不需要后端额外返回总条数，但只能判断是否存在下一页。

## 读取表单

```javascript
const formData = new FormData(form);

const payload = {
  amount: Number(formData.get("amount")),
  category: formData.get("category"),
  note: formData.get("note") || null,
};
```

- `new FormData(form)`：读取表单中具有 `name` 的控件；
- `formData.get("字段名")`：取得某个字段的值；
- 表单值默认是字符串；
- `Number()`：把金额字符串转换为数字；
- `值 || null`：空值时使用 `null`。

## JavaScript 对象与 JSON

```javascript
const payload = {
  amount: 20,
  category: "交通",
  note: "公交",
};

const jsonBody = JSON.stringify(payload);
```

- `{ key: value }`：JavaScript 对象；
- `payload.amount`：读取对象属性；
- `JSON.stringify()`：把 JavaScript 数据转换为 JSON 字符串；
- JavaScript 对象不等于 JSON 字符串。

模板字符串：

```javascript
const text = `${payload.category}：${payload.amount} 元`;
```

## 接口数据转换为图表数据

图表库需要有尺寸的 DOM 容器，然后才能创建实例并设置配置：

```html
<div id="category-chart" style="width: 600px; height: 320px"></div>
<div id="daily-chart" style="width: 600px; height: 320px"></div>
```

```javascript
const categoryChart = echarts.init(
  document.querySelector("#category-chart"),
);

categoryChart.setOption({
  series: [
    {
      type: "pie",
      data: categorySummary.map((item) => ({
        name: item.category,
        value: item.amount,
      })),
    },
  ],
});
```

基本链路：

```text
有尺寸的 DOM 容器 → 图表实例 → option/series → setOption()
```

接口响应结构通常不等于图表库的数据结构，需要用 `.map()` 转换数据契约：

- 饼图：每项转换为 `{ name, value }`；
- 折线图：分别生成类别横轴数组和数值数组。

```javascript
const dailyChart = echarts.init(document.querySelector("#daily-chart"));
const dates = dailySummary.map((item) => item.date);
const amounts = dailySummary.map((item) => item.amount);

dailyChart.setOption({
  xAxis: {
    type: "category",
    data: dates,
  },
  yAxis: {
    type: "value",
  },
  series: [
    {
      type: "line",
      data: amounts,
    },
  ],
});
```

聚合接口中的字段语义：

- `amount`：已经是该组记录的金额总和；
- `count`：该组包含的记录数；
- 不能再计算 `amount * count`，否则会重复累计。

新增、编辑或删除数据后，列表和图表都是同一数据源的派生视图，需要一起刷新：

```javascript
await Promise.all([loadExpenses(), loadCharts()]);
```

排错时先用静态数据调用 `setOption()`，确认容器尺寸、实例和图表配置正确，再连接真实接口。这样可以区分渲染问题与数据问题。

## POST 请求

```javascript
const response = await fetch(API_URL, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Token": TOKEN,
  },
  body: JSON.stringify(payload),
});

if (!response.ok) {
  const detail = await response.text();
  throw new Error(`创建失败：${response.status} ${detail}`);
}
```

| 配置 | 作用 |
| --- | --- |
| `method` | HTTP 方法 |
| `headers` | 请求头 |
| `Content-Type` | 请求体的数据格式 |
| `X-Token` | 项目约定的认证请求头 |
| `body` | 请求体 |

`fetch()` 遇到 `404`、`422`、`500` 时通常不会自动抛错，必须检查 `response.ok`。

## 提交成功后的处理

```javascript
form.reset();
await loadExpenses();
```

- `form.reset()`：清空或恢复表单；
- 它不会更新数据列表；
- POST 成功后重新 GET，才能显示最新数据。

`location.reload()` 会重新加载整个 HTML 页面；`reset()` 加 `loadExpenses()` 只重置表单并重新获取列表数据，属于局部重绘。

## 错误处理

```javascript
try {
  await loadExpenses();
} catch (error) {
  console.error(error);
}
```

- `throw new Error()`：主动抛出错误；
- `try...catch`：捕获网络错误、解析错误和主动抛出的错误；
- `response.ok` 判断 HTTP 状态，`try...catch` 处理被抛出的错误。

## CORS

协议、主机、端口任意一项不同，就是不同源：

```text
http://127.0.0.1:5500
http://127.0.0.1:8000
```

FastAPI 配置：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://127.0.0.1:5500"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

- CORS 是浏览器的跨源读取限制；
- `allow_origins` 必须包含前端页面的来源；
- JSON 请求或自定义请求头通常会触发 `OPTIONS` 预检；
- 接口能直接打开，不代表网页中的跨源 `fetch` 一定成功；
- 缺少 `Access-Control-Allow-Origin` 时，浏览器会阻止 JavaScript 读取响应。

如果业务接口和 `/openapi.json` 同时返回 `404`，先确认当前端口运行的是不是目标应用。请求发到错误服务时，路由不存在才是根因，浏览器显示的 CORS 报错可能只是次级现象，不能直接靠修改跨域配置解决。

## 前后端字段对应

| 前端 | 后端 |
| --- | --- |
| 控件的 `name` | 请求模型字段名 |
| `option.value` | 枚举允许值 |
| `Number()` 后的值 | 数字类型字段 |
| `Content-Type` | 请求体解析方式 |
| `X-Token` | 认证请求头 |

字段名必须完全一致，例如 `note` 和 `notes` 是两个字段。

可选字段要使用非空值测试。只测试空备注时，拼写错误可能被 `null` 掩盖。

## 排错顺序

| 层次 | 检查内容 |
| --- | --- |
| DOM | 选择器是否找到元素，事件是否触发 |
| 表单 | 是否有 `name`，`FormData` 的键和值是否正确 |
| 请求 | URL、方法、请求头、Request Payload |
| CORS | `OPTIONS` 和 `Access-Control-Allow-Origin` |
| 后端 | 状态码、响应体、`422` 校验信息 |
| 数据库 | 数据是否真的新增或修改 |
| 渲染 | GET 已返回数据，但 DOM 是否正确更新 |

Console 报错还要检查脚本来源。`content*.js` 等文件可能由浏览器扩展注入，不一定是项目代码。
